# 02 · 设计说明 —— 企业产业链研判（读时研判 + 规则可解释）

> 配套：同目录 `01-需求.md`；口径 B：真实业务模块 + 一林标准分层；研判结果读时计算、不落库（MVP 只读）；菜单走数据库。

## 1. 总体架构与数据流

双工程、前后端分离（市面标准形态）：

| 工程 | 位置 | 技术栈 | 端口 |
| --- | --- | --- | --- |
| 后端 | `D:\iTwoLeg\OPC项目\RuoYi-Vue`（分支 feat/opc-demo） | JDK 1.8 + Spring Boot 2.5.15 + MyBatis + MySQL/H2 + Redis | 8080 |
| 前端 | `D:\iTwoLeg\OPC项目\RuoYi-Vue3`（分支 feat/opc-demo） | Vue 3.5 + Vite 6 + Element Plus + Pinia | 80 |

研判数据流：

浏览器 → Vite（/dev-api 代理）→ 后端 8080 `/system/assess/*` → BizAssessController → IBizAssessService（读 biz_company / biz_company_metric / biz_chain / biz_chain_node / biz_company_chain）→ 归属解析 + AssessScoreEngine 评分 → 返回 VO。

架构决策：

- 研判结果**读时计算**：归属解析与评分均在查询链路完成，不建“研判结果表”，保证口径一致、无脏数据；二期需留痕/审计时再物化 biz_assess_record。
- 数据底座与研判逻辑解耦：本环境画像/图谱无数据，以种子补齐；未来接真实两模块数据时，只需替换 5 张表的数据来源，Service/评分引擎不变。
- 归属双轨：预挂接为主（primary_flag=1），关键词兜底为次；兜底必须回显命中词证据。
- 评分可解释：每个维度返回 得分/满分/数据取值/规则命中说明，杜绝黑盒。

## 5. 归属解析（企业 → 链/环节）

输入：企业主档（company_id、main_product、business_keywords）。

1. 取 `biz_company_chain` 中 company_id 匹配且 del_flag='0'、primary_flag='1' 的行 → 命中即预挂接（link_type='1'），优先使用库内 link_role/evidence。
2. 无预挂接 → 关键词兜底：将 main_product + business_keywords 与各启用环节的 keywords 做包含匹配（逗号/中文逗号分词，忽略大小写）。
3. 多环节命中时按优先级取一条：importance_level 升序（关键核心优先）→ gap_type 缺链(1)优先 → node_order 升序；link_type='2'，link_role 由环节 gap_type 推导（1缺链→补链、2弱链→强链、3优势成熟→延链），evidence=「业务关键词命中：xx（环节关键词：yy）」。
4. 均未命中 → 未归链：列表显示“未归链”，不参与评分，详情给出引导文案（补充挂接或完善业务关键词）。

示例：汉和电驱科技 主档关键词含“车用电驱动电机电控”，命中「关键零部件」环节 keywords（电机/电控/电驱），环节 gap_type=2（弱链）→ link_role=强链，evidence 展示命中词。

## 6. 评分引擎与建议（默认口径，常量集中于 AssessScoreEngine）

总分 = 正向四项之和 − 风险扣分，取 0–100（保留 1 位小数）。

| 维度 | 满分 | 规则（分值均按档位取，可单测） |
| --- | --- | --- |
| 环节关键度 | 30 | 基础：关键核心 18 / 重要支撑 12 / 一般配套 7；缺口加成：缺链 +12 / 弱链 +7 / 优势成熟 +3；合计上限 30 |
| 经营成长 | 25 | 营收增速：≥40% 14 / 20–40% 11 / 0–20% 8 / -20–0% 4 / < -20% 0；利润增速：≥30% 7 / 10–30% 5 / -10–10% 3 / < -10% 0；注册资本：≥10000 万元 4 / ≥5000 3 / ≥1000 2 / 其他 1 |
| 创新实力 | 25 | 高企 1 是 +6；有效专利：≥100 9 / ≥30 7 / ≥10 5 / ≥1 3 / 0 0；研发强度：≥10% 10 / ≥5% 8 / ≥3% 6 / ≥1% 4 / <1% 2；合计上限 25 |
| 融资热度 | 20 | 轮次：已上市 15 / D+ 15 / C 12 / B 9 / A 7 / 天使 5 / 未融资 0；时间新鲜度：≤6 个月 +5 / ≤12 +4 / ≤24 +2 / 更早或未融资 +0；合计上限 20 |
| 风险扣分 | 0–20 | risk_level：0 无扣 / 1 低 扣 4 / 2 中 扣 8 / 3 高 扣 14 / 4 重大 扣 20；l lawsuit/abnormal 数量仅作为证据展示，不重复扣 |

维度证据卡（每维输出）：维度名、得分/满分、数据取值、规则命中说明。例如「创新实力 23/25：高企 是（+6）；有效专利 128（≥100，+9）；研发强度 9.8%（≥5%，+8）」。

等级与建议：

| 等级 | 区间 | 建议动作（模板） |
| --- | --- | --- |
| A | ≥85 | 建议重点招商/优先对接：企业处于「链-环节」{缺口态}，{补/强/延}链价值高，建议纳入区级重点招商名单，优先匹配载体与政策 |
| B | 70–84.9 | 建议重点合作/培育跟踪：整体良好，纳入重点走访名单；短板维度为「xx」，补齐后可升级评估 |
| C | 55–69.9 | 建议一般跟踪：基础一般，短板维度为「xx」，择机接触并持续观察指标变化 |
| D | <55 | 建议暂缓/观察：风险项突出（{risk_note}），暂缓招商资源投入，优先完成风险核实 |

短板识别：某维度得分率 < 50% 视为短板，取最低一条拼入建议文案；D 档优先呈现风险而非短板。

工作示例（青藤动力能源科技，目标 A）：环节关键度 30（关键核心+缺链）＋经营成长 25（营收增速 45%→14、利润 60%→7、注册资本 5 亿→4）＋创新实力 23（高企+专利 128+研发 9.8%）＋融资热度 17（C 轮+近 6 月）− 风险 0 = 95 分 → A。

## 7. 接口设计

统一响应 `{code,msg,data}`；分页遵循 TableDataInfo；权限 `system:assess:list / system:assess:query`。

| # | 方法与路径 | 说明 | 权限 |
| --- | --- | --- | --- |
| 1 | GET /system/assess/chains | 链+环节级联（全启用链，含环节列表） | list |
| 2 | GET /system/assess/list | 研判列表：分页+条件 | list |
| 3 | GET /system/assess/statistics | 统计卡 | list |
| 4 | GET /system/assess/detail/{companyId} | 研判详情 | query |
| 5 | GET /system/assess/graph?chainId= | 加分：链→环节→企业反查 | query |

列表参数：pageNum/pageSize、companyName（模糊）、chainId、nodeId、grade（A/B/C/D，映射为分数区间过滤）、minScore/maxScore、linkType。排序默认 totalScore desc、companyId asc。

实现要点：Service 一次查出“企业+指标快照+主挂接+链/环节”（del_flag 均过滤，biz_company 全量含未归链），逐行跑归属解析与评分（演示规模 ≤ 数千条），再内存筛选、构造 `Page` 手工分页（列表与统计共用同一评分结果，保证口径一致）。规模化后改为结果物化或规则下推，见第 13 节。

## 8. 前端页面设计

### 8.1 企业研判总览 index.vue

## 13. 风险与对策、二期方向

| 风险/取舍 | 对策/说明 |
| --- | --- |
| 读时评分随数据量增长变慢 | MVP 演示规模 OK；规模化后物化 biz_assess_record 或评分规则下推 SQL，引擎入参不变 |

| H2/MySQL 方言差异 | 双脚本分离维护，构建与双模式冒烟纳入 03-测试 |
