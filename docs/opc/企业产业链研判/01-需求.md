# 01 · 需求说明 —— 企业产业链研判（OPC 演练场景）

> 所属套件：OPC 机试 30 分钟交付套件（RuoYi-Vue 后端 + RuoYi-Vue3 前端，前后端分离）
> 场景来源：现场 OPC 测试题「企业画像 × 产业链图谱 → 企业产业链研判」
> 本文件为 30 分钟时间盒 0–2 分钟产物；后续将依次产出 02-设计 / 03-测试 / 04-交付 / 05-实战手册（每步先确认再推进）

## 1. 场景背景与目标

公司现有两个相互独立的模块：

- 企业画像：展示企业基本信息、经营、创新、融资、风险等数据；
- 产业链图谱：展示产业链环节、产品及相关企业。

业务人员看完一家企业，仍回答不了四个问题：

1. 企业到底属于哪条产业链、哪个环节；
2. 企业在产业链中的价值是什么（补链/强链/延链）；
3. 是否值得招商、合作或重点跟踪；
4. 系统给出的判断依据是什么。

本期目标：新增「企业产业链研判」功能，把画像与图谱打通，围绕一家企业输出「链环节定位 + 综合评分等级 + 分维得分 + 判断依据 + 行动建议」，支撑招商决策与日常跟进。

## 2. 澄清问题与结论

| # | 澄清问题 | 业务方答复 | 由此落定的默认口径 |
| --- | --- | --- | --- |
| 1 | 企业画像、产业链图谱两个模块底层是否有结构化数据表 | 没有 | 本环境需补齐「演示最小数据底座」：产业链/环节/企业画像主档/指标快照/企业-环节挂接，含种子数据；研判逻辑与数据来源解耦，未来接入真实两模块数据只换数据、不改规则 |
| 2 | 研判对象范围 | 只针对画像库内企业 | 不做任意企业名查询、不做外部数据源/爬虫/工商接口，列表只出画像库企业 |
| 3 | 是否有现成招商评估维度与权重 | 没有 | 采用市场默认五维可解释模型：环节关键度 + 经营成长 + 创新实力 + 融资热度（正向），风险负向修正；演示期权重/阈值以常量配置，讲解时声明可调 |
| 4 | 30 分钟验收口径 | 正向为主，可以 | 主验收＝企业→链/环节定位 + 总分等级 + 分维得分 + 判断依据 + 行动建议；反向「链→环节→企业」列为加分项 |
| 5 | 归属方式（市场对标定稿） | — | 预挂接为主 + 关键词兜底：优先读企业-环节挂接（人工/上游图谱维护）；无挂接时按主营产品/业务关键词匹配环节关键词，命中即兜底归链并回显命中证据 |
| 6 | 结果形态（市场对标定稿） | — | 综合评分（百分制）+ A/B/C/D 等级 + 建议动作；不输出黑盒结论，每条分数都能下钻到取值与规则 |
| 7 | 数据是否可编辑 | — | MVP 只读：研判结果读时实时计算，不落库、不提供编辑；画像与挂接的维护不在本期范围 |

## 3. 名词与口径

- 企业产业链研判：对画像库内企业，给出其主链、主环节、链价值角色与招商动作建议的综合评估。
- 补链/强链/延链：按企业所处环节在本地链中的成熟度取值——缺链环节补链价值最高、弱链环节强链价值次之、成熟环节延链/升级。
- 主链/主环节：一家企业本期只取一条主链、一个主环节（挂接表 primary_flag=1）；多归属留作二期。
- 归属依据：分为「预挂接（人工/上游模块维护）」与「关键词兜底（命中词明细）」两类，页面上必须可见。

## 4. 功能清单

| 功能 | 说明 | 验收点 |
| --- | --- | --- |
| F1 数据底座与种子 | 2 条产业链 × 每链 5–6 个环节；12–15 家画像企业覆盖 A–D 档；含预挂接与关键词兜底样例 | 双库（MySQL/H2）均可起，登录后数据可查 |
| F2 研判总览 | 统计卡片（画像企业总数 / 已归链数 / A 重点招商数 / B / C / D）+ 企业列表（分页，筛选：链、环节、等级、得分区间、企业名关键词），列含企业、主链/主环节、归属方式、总分、等级、建议动作 | 筛选组合正确、统计与列表口径一致 |
| F3 企业研判详情 | ①定位：主链/主环节/价值角色 + 归属依据；②综合：总分 + 等级 + 建议动作；③分维明细：每维得分/满分/取值/规则命中说明；④风险项与提示 | 任意一家已归链企业均可展示完整正向链路 |
| F4 判断依据与建议 | 打分卡式依据明细（为什么是这个分、数据取值是什么）+ 动作建议按等级与短板自动生成 | 无“黑盒结论”，每条依据可复述 |
| F5 反向浏览（加分） | 链 → 环节 → 企业反查；环节内企业评分排序 | 有时间则做，作为加分项展示 |
| F6 权限与品牌 | 菜单/按钮权限走 sys_menu；页面文案为「一林」，无若依字样 | 无权限按钮不渲染，页面无红屏无报错 |

## 5. 验收标准

- [ ] MySQL 与 H2 双模式启动成功，admin/admin123 登录后「产业链研判」菜单可用
- [ ] 主验收正向链路全通：任一已归链企业 → 详情页能同时看到 链/环节定位、归属依据、总分与等级、五个维度得分及依据、行动建议
- [ ] 评分可解释可复算：同一企业两次查看结果一致；改动种子指标后分数按规则变化，依据卡文字与取值一致
- [ ] 至少 1 家企业走「关键词兜底」且证据可见；至少 1 家触发风险扣分；A/B/C/D 四档均有样例可讲
- [ ] 统计卡片与列表数据一致；控制台无报错
- [ ] 符合一林/若依标准规范：表无 TEXT/BLOB/JSON 大字段、金额 DECIMAL、状态 CHAR + 字典、菜单走数据库、前端沿用 request/字典/权限封装
- [ ] 反向加分项完成度在 04-交付 中如实标注（做成/未做/半成品）

## 8. 评分与建议默认口径（口子先定，公式 02-设计定稿）

正向四项满分合计 100：环节关键度 30、经营成长 25、创新实力 25、融资热度 20；再按风险档扣 0–20 分，总分 0–100。

| 维度 | 权重 | 看什么 | 典型依据 |
| --- | --- | --- | --- |
| 环节关键度 | 30 | 环节重要性 × 缺口态（补链/强链/延链价值） | 环节为“缺链+关键核心”→ 高分档 |
| 经营成长 | 25 | 营收/利润增速、规模 | 增速、注册资本、成立年限 |
| 创新实力 | 25 | 专利、研发强度、高企资质 | 有效专利数、rd_ratio、high_tech_flag |
| 融资热度 | 20 | 融资轮次、金额、时间新鲜度 | last_finance_round/amount/date |
| 风险修正 | -0~20 | 涉诉、异常、风险档 | risk_level、l lawsuit_count 等 |

等级与建议：A ≥85 重点招商（优先资源对接）；B 70–84 重点合作/培育（纳入重点走访）；C 55–69 一般跟踪（择机接触，先补短板）；D ＜55 暂缓观察（风险优先核实，不建议投招商资源）。动作建议文案 = 等级映射 + 短板提示 + 价值角色（补链/强链/延链）。
