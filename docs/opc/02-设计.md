## 3. 表结构（MySQL）

```sql
CREATE TABLE biz_project (
  project_id     BIGINT       NOT NULL AUTO_INCREMENT COMMENT '项目ID',
  project_name   VARCHAR(100) NOT NULL COMMENT '项目名称',
  project_code   VARCHAR(50)           COMMENT '项目编号',
  industry_type  VARCHAR(30)           COMMENT '行业类型(字典 biz_industry)',
  invest_amount  DECIMAL(14,2)         COMMENT '计划投资额(万元)',
  project_status VARCHAR(10)  NOT NULL DEFAULT '0' COMMENT '状态(0洽谈中 1已签约 2已落地)',
  sign_date      DATE                 COMMENT '签约日期',
  landed_date    DATE                 COMMENT '落地日期',
  contact_name   VARCHAR(50)           COMMENT '联系人',
  owner          VARCHAR(50)           COMMENT '招商负责人',
  remark         VARCHAR(500)          COMMENT '备注',
  create_by      VARCHAR(64)           COMMENT '创建者',
  create_time    DATETIME              COMMENT '创建时间',
  update_by      VARCHAR(64)           COMMENT '更新者',
  update_time    DATETIME              COMMENT '更新时间',
  PRIMARY KEY (project_id),
  KEY idx_status (project_status)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='招商项目库';
```

说明：删除走标准 CRUD 物理删除（与若依生成器默认一致）；金额小数保留两位；名称/编号检索建普通索引即可（数据量为演示级）。

## 5. 状态机与统计

### 5.1 状态字典 `biz_project_status`

| value | label | 说明 |
| --- | --- | --- |
| 0 | 洽谈中 | 初始态 |
| 1 | 已签约 | 由 0 推进，自动写 sign_date（空时） |
| 2 | 已落地 | 由 1 推进，自动写 landed_date（空时） |

规则：只允许 0→1→2 逐级推进；目标状态 = 当前状态 +1，否则返回 500 + 业务提示；推进失败不落库（Service 事务）。

### 5.2 统计接口

`GET /system/project/statistics` 返回：

```json
{ "code": 200, "msg": "操作成功",
  "data": { "total": 12, "negotiating": 5, "signed": 4, "landed": 3 } }
```

实现：单条 SQL 按 project_status 分组计数，避免多次查询（无 N+1）。

## 7. 双数据库模式

| 模式 | 激活 profile | 数据源 | 启动 |
| --- | --- | --- | --- |
| MySQL（默认） | druid | jdbc:mysql://localhost:3306/ry-vue | `java -jar ruoyi-admin.jar` |
| H2 内存（保底） | h2 | jdbc:h2:mem:ry;MODE=MySQL;DB_CLOSE_DELAY=-1 | `java -jar ruoyi-admin.jar --spring.profiles.active=h2` |

H2 通过 `spring.sql.init` 加载 `sql/opc/h2/schema-h2.sql` 与 `data-h2.sql`（含登录所需 sys_* 核心表、字典、菜单与 biz_project 种子），不依赖外部 MySQL/Redis 之外服务——Redis 仍为登录所需（本机已装本地版，见 04）。

说明：H2 为机试保底，Redis 是本机 `E:\Program Files(AI)\tools\redis` 启动的本地实例；H2 模式不改变任何业务代码。

## 8. 换场景机制（口径 B）

换场景 = 替换下列“三件套”，基线模块作为标准模板参考，AI 按场景清单代笔：

1. 后端场景 SQL：`sql/opc/scenes/<scene>/01-schema.sql`、`02-menu-dict.sql`、`03-data.sql`（真实业务表、菜单、字典、种子）。
2. 后端模块代码：domain/mapper/xml/service/controller 整组替换为对应业务（保持若依分层与命名规范）。
3. 前端：`src/scene/config.js` + `src/api/system/<biz>.js` + `src/views/system/<biz>/index.vue`。

同构字段约定：名称/编号/类型/状态/金额/业务日期/负责人/备注 为模板核心字段集；差异较大场景以扩展字段方式增量生成（写入手册预案，不承诺 5 分钟内的常规路径）。

## 9. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 状态跳级/回退 | Service 层校验 + 前端按钮按配置只显示“下一步” |
| 统计与列表不一致 | 同一数据源、同一状态字典；03-测试含一致性用例 |
| H2 兼容差异 | 专用 H2 schema/数据脚本，避免 MySQL 方言（KEY/COMMENT 等） |
| 换场景字段超纲 | 手册预案：扩展字段清单 + 模板增量改，预留 5 分钟缓冲 |
